# v0.1.0 — first tagged release

The first tagged state of the `archival-fixtures-demo` suite: a real,
decaying, archivable testnet contract plus the scripts, CI workflows, and
docs that make Soroban state archival observable end to end.

Status:   Healthy, decaying ~1 ledger per 5 s (Critical ≈ 6 days, Archived ≈ 7)

## What's in this release

- **Contract** (`contracts/rapid-expiry-demo`): one persistent entry,
  functions `initialize` / `read` / `touch` / `extend`, unit tests
  configured with the real testnet network parameters (5/5 passing).
  Deliberately no `ttl()` — contracts cannot read their own TTL by
  protocol design; monitoring is off-chain.
- **Scripts** (`scripts/`): deploy-and-shrink-ttl, trigger-eviction-wait,
  run-full-pipeline, read-entry-ttl.py — all verified by execution against
  live testnet (see `.transcripts/`).
- **CI** (`.github/workflows/`): `demo-scan.yml` (scheduled off-chain TTL
  scan, fails red on decay), `demo-restore.yml` (manual restore via
  `RestoreFootprintOp` with the TESTNET-ONLY throwaway key),
  `test-contract.yml` (cargo test on push/PR).
- **Docs**: `docs/surviving-soroban-state-archival.md`,
  `docs/setting-extend-ttl-boundaries.md`, README with real transcript
  captures, CONTRIBUTING, SECURITY.

## Safety

TESTNET ONLY. The throwaway key holds only testnet lumens and can be
discarded at any time. No mainnet key or contract is used anywhere in this
suite.

## Known state at tag time

The Critical → Archived → restore phases of the live demo are pending the
real-time decay (~7 days total); the repo's docs say so plainly rather than
fabricating output. See issue #2 for tracking.
